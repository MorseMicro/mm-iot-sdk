LWIP on-demand timers

On-demand timers introduces lwIP changes that reduce network-stack wakeups by scheduling selected lwIP timers only when protocol state says there is work to do. This is intended for low-power builds where idle and low-traffic power consumption matter more than absolute peak throughput.

Power consumption can be reduced by up to 50% for an associated station with a dormant TCP socket open.

The feature is controlled from the MM-IoT-SDK build system and then passed into the lwIP port as MORSE_LWIP_TIMERS_ON_DEMAND. It is currently only compatible with IPv4.

How it's implemented

The changes made to lwIP implement a Morse on-demand timer layer in src/include/morse/on_demand_timers.h and wires it into ARP, TCP, and netconn state changes.

When MORSE_LWIP_TIMERS_ON_DEMAND=0, the new hooks compile to no-ops and lwIP uses its normal timer behavior.

When MORSE_LWIP_TIMERS_ON_DEMAND=1 (default):

  • src/core/timeouts.c registers on-demand timer descriptors for ARP, TCP fast, and TCP slow timers. Each descriptor has a timer handler, a tick update function, and a sleep_ticks function that returns the next deadline or LWIP_UINT32_MAX when no timer is needed.
  • Timer re-evaluation is batched behind a short internal delay (MORSE_LWIP_TIMERS_EVAL_DELAY_MS, currently 1 ms) so frequent protocol state changes do not immediately rescan all timers.
  • The TCP/IP thread mailbox is kicked with a NULL message after scheduling a re-evaluation so the thread wakes and processes the updated timeout list. Current submodule revisions use sys_mbox_trypost() for this kick so a full mailbox cannot deadlock the TCP/IP thread.
  • src/core/ipv4/etharp.c stops relying on a permanently cyclic ARP timer. ARP cache age is advanced from elapsed time when ARP state is inspected, and ARP schedules its next timer only when entries need expiry, retry, or refresh handling.
  • src/core/tcp.c, src/core/tcp_out.c, src/api/api_msg.c, src/api/sockets.c, src/core/altcp_tcp.c, src/core/pbuf.c, src/core/ipv4/ip4.c, and src/core/ipv6/ip6.c call the new TCP timer hooks around state changes that can affect retransmission, delayed ACK, close, keepalive, poll, TIME_WAIT, send-buffer, or receive processing deadlines.
  • Netconn TCP poll handling is treated specially. If a netconn is idle, the TCP slow timer does not wake just to run the poll callback. It still wakes immediately for pending writes, close processing, or write-space events.

When to enable or disable it

Enable on-demand timers when:

  • the device spends significant time associated but idle;
  • the application sends occasional bursts rather than continuous traffic; or
  • battery life, sleep residency, or low average current is more important than best-case throughput.

Disable on-demand timers when:

  • regularly performing high-bandwidth TCP transactions; or
  • IPv6 is required (not currently compatible).

Troubleshooting

To debug timer decisions, DEBUG_SLEEP_TICKS_ENABLE=1 can be defined in the lwIP build. This prints the calculated sleep deadlines, but the diagnostic printing itself can perturb timing, so it should not be used for power or throughput measurements.
